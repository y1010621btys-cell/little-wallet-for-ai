# 教程 4 · 给 AI 一双眼睛和手（淘宝）

淘宝在手机上没有官方 MCP。解法：在 VPS 上跑一个 Chromium，AI 自己开网页、搜商品、加购物车、截图——等于有了一双不碰你手机的眼睛和手。

> 关于美团：思路基本同理（一样是常驻浏览器 + 登录墙 + 验证码那套坑，照下面的方法搬一遍即可）。但外卖用**淘宝闪购**就能买，跟淘宝共用同一个账号和这套流程，所以我们没再额外去配美团——本篇只讲淘宝。

> 这篇是我们**真的踩通之后**重写的。上一版走的是「用完即退」的一次性浏览器，结果登录态老是掉、验证码上下文老是丢。真正跑通的是下面这套：**一个常驻浏览器 + 加购接口绕验证码**。

## 内存警告（先看这个）

Chromium 很吃内存。1G 内存的小机器**必须先加 swap**，否则会把别的服务挤死：

```bash
# 已有 swap 的跳过（swapon --show 查看）
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo "/swapfile none swap sw 0 0" >> /etc/fstab
```

## 核心思路：一个常驻浏览器，别开了又关

我们最开始信奉「按需启动、用完即退、绝不常驻」——每次操作开一个新的 headless Chromium，截完图就关。**这是错的**，至少对淘宝这种硬风控站点是错的：

- 登录是「机器发码 → 人读短信 → 机器回填」的人机接力，中间那几分钟里浏览器一关，**会话和验证码上下文全丢**，很多平台的码是绑当前会话的，换个浏览器就作废；
- 就算扫码登录成功，headless 浏览器的自动化指纹也常被识破，cookie 不落地，刷新又回到未登录。

真正稳的做法：**开一个 headed（有头）Chromium，用 xvfb 假装有屏幕，用 systemd 常驻不关，开着 CDP 调试端口。** 需要操作时，脚本连进这个调试端口做事，做完就**断开连接、但浏览器不关**。登录态一次搞定，长期有效。

安装：

```bash
mkdir -p /root/browser && cd /root/browser
python3 -m venv venv
./venv/bin/pip install playwright websockets
./venv/bin/playwright install chromium --with-deps   # 约300MB
apt-get install -y xvfb                                # 虚拟屏
```

把仓库里 `deploy/taobao-browser.service` 放进 `/etc/systemd/system/`，
按你 playwright 实际装的版本改一下 chrome 路径（`ls ~/.cache/ms-playwright/`），然后：

```bash
systemctl daemon-reload && systemctl enable --now taobao-browser
curl -s http://127.0.0.1:9223/json/version    # 看到 Chrome 版本号就活了
```

这个浏览器现在会一直开着，调试端口挂在 `127.0.0.1:9223`。之后所有操作都靠连它。

## 登录：海外 VPS 就扫码，别死磕短信

连上常驻浏览器，让它开淘宝登录页，然后：

**海外 VPS 的坑：短信区号默认 +1。** 服务器在国外，淘宝把短信区号默认成了美国 +1，中国手机号根本收不到码；而那个改区号的下拉框是跨域 iframe，一动鼠标就收起来，自动化很难点中。**别跟它耗——直接扫码登录。** 让浏览器停在扫码页，把二维码截图发到你手机，淘宝 App 一扫就过，完美绕开区号问题。

**扫完可能还有第二道核验。** 扫码成功后它常再跳一个 `identity_verify` 身份核验页，**又要一次短信校验码**（这个码发到你 App 里，不受 +1 影响）。你把 4 位码报给 AI，它填进去点确定就登进去了。

**反自动化指纹。** 如果你偏要走短信/自动化点按，记得注入反检测脚本抹掉 `navigator.webdriver`（仓库 `browser/login_driver.py` 里的 `STEALTH`），并加启动参数 `--disable-blink-features=AutomationControlled`。走扫码的话这步没那么关键，但加上无害。

登录成功的标志：cookie 里拿到 `cookie2`、`unb`、`_l_g_`、`_tb_token_`、`tracknick` 这几个。有了它们，购物才走得下去。

## 买东西：绕开详情页那道验证码

登进去之后你会发现第二堵墙：**商品详情页（item.taobao.com）对海外 IP 会弹滑块验证码**，自动化拖不过去（它检测拖动轨迹）。这意味着 AI 打不开详情页、看不了规格。

关键发现救场：**加入购物车的接口 `cart.taobao.com/add_cart_item.htm` 不验证。** 所以完全可以跳过详情页——

```
搜索(连浏览器) → 加购(带 cookie 直接调接口) → 递条子 → 你在 App 里选规格付款
```

仓库里的 `browser/tb_buy.py` 就是这套流程，三个命令：

```bash
python3 tb_buy.py search "猫条"          # 连浏览器搜，列出 ID/价格/图
python3 tb_buy.py add 557427283454       # 只加购
python3 tb_buy.py buy 557427283454 \     # 加购 + 递条子
    --title "德国施德楼素描铅笔" --price 4.9 --img "https://gw.alicdn.com/..."
```

`add` 内部就是带着从浏览器取来的 cookie + `_tb_token_`，POST 一下加购接口；成功会返回购物车总件数（你能看到 180 → 181）。`buy` 在加购成功后再调钱包的 `/notes` 递一张申请条，把商品图和链接放进去。

## 进阶：把淘宝也包成一个 MCP

上面是命令行手动跑。如果你想让 **AI 在对话里直接调淘宝**（像教程 3 的麦当劳瑞幸那样——在 claude.ai、在 Telegram 里的 Claude、或你自建 agent 里张口就来），那就把 `tb_buy.py` 再包一层 MCP：仓库里的 `browser/tb_mcp.py` 用 `FastMCP` 把「搜索 / 加购 / 加购+递条子」暴露成三个工具（`taobao_search` / `taobao_add_cart` / `taobao_buy`）。

它跟钱包 MCP 是一模一样的搭法（教程 1 里那个 `mcp_server.py`）：

```bash
cp tb_mcp.py /root/wallet/                    # 和 tb_buy.py 同目录，好 import
./venv/bin/pip install websockets             # tb_buy 要用
# systemd：deploy/wallet-tbmcp.service，监听 127.0.0.1:8009
systemctl enable --now wallet-tbmcp
# nginx：加一条秘密路由 /tb-mcp-<secret>/ → 127.0.0.1:8009/（照 wallet-mcp 块抄）
nginx -t && systemctl reload nginx
```

然后把 `https://你的域名/tb-mcp-<secret>/` 当连接器加进 AI 端就行。**注意这个 MCP 必须跑在能读到常驻浏览器 profile 的用户下（我们用 root）**——它要连 CDP:9223 那个浏览器。加进 Claude Code 一句话：

```bash
claude mcp add --transport http taobao https://你的域名/tb-mcp-<secret>/
```

> 一个提醒：几扇门（`/wallet-api/`、`/wallet-mcp/`、这个 `/tb-mcp-…/`）通到的是同一套后端和同一个浏览器。「下单」这种动作是 **AI 调 MCP** 干的——不管这个 AI 在 Telegram、在 claude.ai、还是在你自己的聊天前端后面，逻辑都一样；纯展示的钱包页面不碰这些，只负责把 AI 递来的条子显示给你看、给你批。换句话说：调工具的是 AI，不是"前端"这个身份（详见教程 1 的"哪里有 AI"那段）。

## 分工与支付原则

AI 做：搜商品、加购物车、把选好的东西截图 + 链接摆进条子。
你做：第一次登录搭把手（报个核验码）、在淘宝 App 里**选规格、付款**。

⚠️ **不开免密支付 / 月付。** 付款永远由人类完成——这不是不信任 AI，是让每一笔钱都有两双眼睛看过。

**关于选规格会改价：** 因为 AI 够不到详情页，加购时没法替你选规格（笔芯硬度、颜色、套装数量……），这些得你在 App 里选。而一选规格、一用优惠券，实际价格常和条子上的估价对不上。所以条子的批复接口留了个 `final_price`：你付完看到真实金额，批准时填进去，账本就**按实际扣**、条子也回写成真实价（页面上「准奏」时会问你一句「实际付了多少」，直接回车＝按估价）。详见教程 1 的接口说明。

## 我们踩过的坑（都是淘宝的）

电商平台的登录风控**就是专门防自动化的**

**坑① 用完即退 = 登录态永远掉。** 开一个浏览器截图就关，下次再开，cookie 和验证码会话全没了。解法就是上面那个常驻 headed 浏览器 + CDP，开着不关。这是整篇最重要的一条。

**坑② headless 会被当场识破。** 默认 headless Chromium 带着 `navigator.webdriver=true` 一堆指纹，淘宝一眼看穿，扫码「成功」也不落 cookie。要么注入反检测脚本，要么直接用 headed（xvfb 撑起虚拟屏），我们最后走的是 headed。

**坑③ 海外 VPS 短信区号默认 +1。** 中国号收不到码，改区号的下拉又是跨域 iframe 难点中。**扫码登录**一步绕过。

**坑④ 登进去还有第二道身份核验。** 扫码后常再跳 `identity_verify` 要一次短信码（这个发到 App，不受 +1 影响），报给 AI 填掉即可。

**坑⑤ 详情页对海外 IP 弹滑块验证码，拖不过。** 别硬啃滑块——**加购接口不验证**，跳过详情页直接加购，规格留给人在 App 里选。

**坑⑥ 同一个 profile 同时只能开一个进程。** 常驻浏览器已经锁着 `profiles/taobao-live/`，别再跑第二个脚本去开同一个 profile——用 CDP 连那个已经开着的，而不是新开一个。

## 风险提示

- 电商风控看 IP，海外 VPS 更容易触发再验证——上面那些坑就是它的日常手段，属正常，跟着流程走即可
- `profiles/` 目录含登录 cookie，`WALLET_PHONE` 是你的手机号，`.tb_cookies_cache` 是导出的 cookie，**都不要提交进 git**（本仓库 `.gitignore` 已排除 `profiles/`）
- 常驻浏览器是唯一「常驻」的例外，给它 `MemoryMax` 兜着，1G 机务必先加 swap
- 淘宝桌面版官方其实在内测一个 `taobao-native` CLI（带 MCP），但目前是白名单限制，普通账号用不了；等它公测，可能会比浏览器方案更省心
