# 教程 4 · 给 AI 一双眼睛和手（淘宝/美团等无 MCP 平台）

淘宝、美团在手机上没有官方 MCP。解法：在 VPS 上跑一个按需启动的 Chromium，AI 自己开网页、点按钮、输文字、截图——等于有了一双不碰你手机的眼睛和手。

## 内存警告（先看这个）

Chromium 很吃内存。1G 内存的小机器**必须先加 swap**，否则会把你机器上别的服务挤死：

```bash
# 已有 swap 的跳过（swapon --show 查看）
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo "/swapfile none swap sw 0 0" >> /etc/fstab
```

原则：**按需启动、用完即退、绝不常驻**。（登录时会破一次例，见下文。）

## 安装

```bash
mkdir -p /root/browser && cd /root/browser
python3 -m venv venv
./venv/bin/pip install playwright
./venv/bin/playwright install chromium --with-deps   # 会下载约300MB，耐心
```

把仓库里 `browser/drive.py` 放进来，改一下开头的截图输出目录。

## 用法：一次性截图

```bash
# 打开淘宝首页截图（profile 会保存登录态，登录一次长期有效）
./venv/bin/python drive.py shot taobao "https://main.m.taobao.com/" taobao-home 8
```

截图会输出到你配置的目录（建议放网站目录下，AI 可以把截图链接直接放进小条子给你看）。

## 登录：为什么 `shot` 不够

`shot` 是「开页 → 截图 → 关」的一次性动作。但登录是一段**人机接力**：

> 机器打开登录页 → 机器点「发送验证码」 → **你**手机收到短信 → **你**把码发给机器 → 机器填进去点登录

中间那两步在人类这边，快则十几秒慢则几分钟。如果每次操作都开一个新浏览器，**会话和验证码上下文全丢**——很多平台的验证码是绑当前会话的，换个浏览器就作废。

所以登录要用**常驻会话 + 指令文件**：浏览器开着不关，轮询一个文本文件，你（或你的 AI）往文件里写一行指令，它读到就执行、把当前状态回写另一个文件。仓库里的 `browser/login_driver.py` 就是这个模式。

```bash
# 先设手机号（不写进代码，不入库）
export WALLET_PHONE=1xxxxxxxxxx

# 启动常驻登录会话（后台跑，别用 sleep 等它）
setsid ./venv/bin/python login_driver.py taobao >/root/browser/taobao.log 2>&1 &
```

然后用指令文件遥控它（另一个终端，或让 AI 用它的 shell 工具写）：

```bash
D=/root/browser
echo -n "SNAP"        > $D/taobao_cmd.txt   # 重新截图看现况
echo -n "SEND"        > $D/taobao_cmd.txt   # 点「发送验证码」
echo -n "CODE:123456" > $D/taobao_cmd.txt   # 你收到码后，填码并提交
echo -n "QUIT"        > $D/taobao_cmd.txt   # 收工

cat $D/taobao_result.txt                    # 看它走到哪步了（含页面文字摘要）
```

`login_driver.py` 顶部的 `PLATFORMS` 字典里预置了淘宝和美团的脾气（登录入口、要不要反检测、要不要勾协议、按钮文案候选）。加别的平台照着填一条就行。

## 分工与支付原则

AI 做：选店、挑规格、加购、下单、盯进度。人类只在第一次登录搭把手（收验证码）。

⚠️ **不要开免密支付/月付**。AI 挑好东西截图放条子，付款永远由人类完成——这不是不信任 AI，是让每一笔钱都有两双眼睛看过。淘宝下单流程：AI 浏览器挑好 → 截图 + 商品链接放进**通知条** → 你自己去付 → 付完点「知道了」→ 钱包扣账。和教程 3 的瑞幸付款链接同款。

## 我们踩过的坑

电商平台的登录风控**就是专门防自动化的**，别指望一次顺。

**坑① 淘宝：无头浏览器会被当场识破**
默认的 headless Chromium 带着 `navigator.webdriver=true` 等一堆自动化指纹，淘宝一眼看穿——二维码扫「成功」了，cookie 却不落，刷新回到未登录。解法是注入一段反检测脚本（`login_driver.py` 里的 `STEALTH`，抹掉 webdriver 标记、伪造 `chrome`/`languages`），并加启动参数 `--disable-blink-features=AutomationControlled`。加了之后我们才真正拿到 `cookie2`、`_tb_token_`、`tracknick` 这些登录 cookie。

**坑② 淘宝：登进去还有第二道核验**
扫码/短信登录成功后，它常再跳一个 `passport.taobao.com/iv/identity_verify.htm` 身份核验页，**又要一次短信校验码**。所以别以为发一次码就完——`login_driver.py` 的指令循环支持你连着发第二次 `SEND` + `CODE:`。另外登录态的**跨进程保鲜**要留心：同一个 profile 换个进程去复验，偶尔又被弹回登录页，重登一次即可，别慌。

**坑③ 美团：灌进去的定位它不认**
给浏览器设 `geolocation` 参数，美团外卖 H5 根本不理，首页永远转圈「定位中」。必须走它自己的「选择城市 → 输地址」流程。而一点「选择城市」，立刻撞登录墙（`poipicker` 跳 `login`）——也就是说不登录连店都看不到。

**坑④ 美团：协议勾选框不勾就登不了**
手机号、验证码都填对，点登录却没反应，弹个 toast「请先阅读并勾选用户协议」。那个 checkbox 没有稳定的选择器，得用 className 关键词 + 坐标兜底去点它（`login_driver.py` 的 `tick_agreement`），而且**填码后、点登录前最好再补勾一次**，它有时会重置。

**坑⑤ 美团：验证码绑会话，中途重启即失效**
验证码是绑当前浏览器会话的。如果你发完码、换个脚本或重开浏览器再填，报「验证信息丢失，请重新发送验证码」。**发码和填码必须在同一个常驻会话里完成**——这正是上面那套指令文件模式存在的理由。

**坑⑥ 同一个 profile 同时只能开一个进程**
Chromium 会锁 `profiles/<平台>/` 目录。你已经有一个登录会话开着，又跑一个脚本去读同一个 profile，第二个会抢锁失败或卡死。去验证登录态之前，先 `pkill` 掉占用的进程。

## 风险提示

- 电商风控看 IP，海外 VPS 更容易触发再验证——上面那些坑就是它的日常手段，属正常，跟着流程重走一遍即可
- `profiles/` 目录含登录 cookie、`WALLET_PHONE` 是你的手机号，**都不要提交进 git**（本仓库 `.gitignore` 已排除 `profiles/`，手机号走环境变量）
- 登录会话是唯一「常驻」的例外，登完记得 `QUIT` 或 `pkill`，别让 Chromium 一直占着那 1G 内存
